**Severity:** Medium

`dashboard/index.html` has one fully keyboard-accessible interactive
widget — the PR-reference card, built on native `<a>` anchors with
`role="note"` + `aria-describedby`, documented in
`docs/DASHBOARD-SPEC.md` as supporting keyboard focus and Enter-activation.
Three other interactive surfaces are click-only: cycle rows that expand
per-stage detail, void-item rows that expand truncated text, and
fleet-node cards that filter the cycle list/log to one node — all plain
elements styled only with `cursor:pointer`, none with `tabindex`,
`role="button"`, or a `keydown` handler.

The PR-reference card was likely built with keyboard support because it
reused native anchor semantics for other reasons (a real link target); the
other three widgets were built as plain clickable `<tr>`/`<div>` elements
without anyone revisiting keyboard access once the pattern was set.

**Ongoing cost:** this is the project's one real interactive UI. A
keyboard-only user cannot expand any cycle's stage detail, cannot read a
truncated void item's full text, and cannot filter the fleet/log to one
node — a large share of the page's functionality.

**Suggested fix:** give the three `.clickable` interaction points
`tabindex="0"`, `role="button"`, and a `keydown` handler for Enter/Space,
mirroring the PR-reference card's existing pattern; update
`docs/DASHBOARD-SPEC.md` to document the added keyboard support in the same
PR, per this repo's as-built-spec convention.
