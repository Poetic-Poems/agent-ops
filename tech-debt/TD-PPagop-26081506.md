Found reviewing TD-PPagop-26081503 (PR #437). That item converted the
`github_json` build's own `--argjson prs`/`--argjson claims` (requirement
4g), but two sites upstream of it, in the same per-repo PR-gathering loop and
the merge-queue badge pass that follows it, still carry the fleet-wide
`prs_json` accumulator into `jq` as `--argjson`. The PR's own Implementer
noticed both and left them out of scope, exactly as the item's four-site
enumeration required — but neither was filed.

None is known to be near `MAX_ARG_STRLEN` (131072 bytes) today, on the same
terms already established for TD-PPagop-26081501, -26081502 and -26081503.

- `scripts/publish-dashboard.sh:1401` — `--argjson add "$prs"` in the
  per-repo PR fold: one repo's whole open-PR-with-label listing, added into
  the running fleet-wide `prs_json` accumulator every iteration of the
  per-repo loop (`$prs_json` itself already arrives on stdin here — it is
  the incoming per-repo page that does not). TD-PPagop-26081503's own
  `gather-source-state.sh` conversion treated an equivalent single-repo
  listing (that script's `$open_prs`) as exactly this kind of value.
- `scripts/publish-dashboard.sh:1628` — `--argjson prs "$prs_json"` in the
  merge-queue queue-answers merge, immediately after the per-repo loop above
  has finished folding every repo in: by this point `$prs_json` is the whole
  cross-repo PR index, the very value TD-PPagop-26081503's `github_json`
  conversion (further downstream in this same tick) now delivers on stdin
  instead.

The fix is the same mechanical conversion the three predecessor items
established: concatenate the documents, deliver with a here-string, bind
positionally with `input as $name`, and leave only configuration-bounded
values (`$slug`, `$at` and similar) in argv. `test/publish-dashboard.test.sh`
already has the extract_block precedent for a build inside this same script
that cannot be driven end-to-end (TD-PPagop-26081503's own `github_json`
test); follow it for whichever of these two sites the real script can't
drive directly either.

Requirement 4g in `docs/IMPLEMENTATION-PIPELINE-SPEC.md` names this item
alongside TD-PPagop-26081501 and TD-PPagop-26081502 as the residue
outstanding after TD-PPagop-26081503.
