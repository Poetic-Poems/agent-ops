agent-ops#391 found that `reviewDecision` never becomes `APPROVED` on a
repository whose branch ruleset sets `required_approving_review_count: 0` —
agent-ops's own setting — however many humans approve a pull request. The fix
(PR closing #391) removed requirement 38c's own dependency on that field:
`scripts/sweep-human-visibility.sh`'s idle nudge now derives "approved" from
the reviews list via `_handoff_pr_approved` (`lib/handoff.sh`).

`scripts/gather-human-visibility-hygiene.sh` (requirement 38e) was not
touched, and it reads the same field for a related purpose:
`docs/IMPLEMENTATION-PIPELINE-SPEC.md`'s requirement 38e describes its
live-recheck for a `could not request review from …` warning as surviving
"only while no human review is currently requested or already given (`gh pr
view --json reviewDecision,reviewRequests` — a pending `reviewRequests` entry
… — or a `reviewDecision` of `APPROVED` or `CHANGES_REQUESTED`, is the
request having worked after all)".

## Why it matters

On agent-ops itself, the `reviewDecision: APPROVED` half of that OR can never
be true, for the same structural reason #391 named. Whether this leaves a
real gap depends on whether the `reviewRequests`-emptying that happens when a
human submits a review is itself sufficient evidence for this re-check to
clear the warning without ever needing the `reviewDecision` half — that has
not been verified. If it is not sufficient, a `could not request review
from …` warning logged against an agent-ops pull request could survive an
approval that should have cleared it, keeping a resolved violation
selectable as `human-visibility` work indefinitely.

## Suggested fix

Read `docs/IMPLEMENTATION-PIPELINE-SPEC.md`'s requirement 38e and
`scripts/gather-human-visibility-hygiene.sh`'s live-recheck together against
a repository with `required_approving_review_count: 0`, and confirm whether
the `reviewRequests`-alone path already covers every case the `reviewDecision`
half was meant to. If it does not, derive "already given" from the reviews
list the same way `_handoff_pr_approved`/`_handoff_blocking_reviewers` now
do, rather than from `reviewDecision`.
