**What.** `docs/REVIEW-PIPELINE-SPEC.md` R12 (as rewritten by agent-ops#876) has the Reviewer-Agent file review-sourced debt with `gh issue create --label pw::type:tech-debt`, relying on the label already existing in the repository under review — 'the label the implementation pipeline's own label catalogue already ensures exists there (requirement 6a)'. That ensure runs only against repositories the *implementation* pipeline gathers: `lib/labels.sh`'s `labels_catalogue` emits `pw::type:tech-debt` for role `target` only, while role `review` — the catalogue `review-cycle.sh`'s own `labels_ensure_role` call (around review-cycle.sh:938) uses per repository about to be reviewed — emits nothing but the resolved review `pr_label` (lib/labels.sh:143-145).

**Why it matters.** `project_review.repos` is its own list in `config.schema.json`, independent of the implementation pipeline's targets. In the shipped configuration the two lists name the same repositories, so R12's claim holds today — but a repository added to `project_review.repos` alone would reach R12's `gh issue create --label pw::type:tech-debt` with the label absent, and the create fails. The failure mode is quiet: the review otherwise completes, and the debt that should have been filed is what gets lost.

**Where.** `lib/labels.sh` `labels_catalogue`, the `role == "review"` branch; consumed by `review-cycle.sh`'s per-repo `labels_ensure_role "..." review "$pr_label"` call.

**Suggested fix.** Add the same fixed `entry("pw::type:tech-debt"; "5319e7"; ...)` line to the `review` role's list in `labels_catalogue` — `review-cycle.sh` already calls `labels_ensure_role` unconditionally for each repository it is about to review, so no new call site is needed. Update requirement 6a's tail (which currently describes the review-role call as covering only the pr_label) in the same PR, and note the fixed-name/trust-anchor rationale already given for the target role applies unchanged. Since the register scripts are canonical upstream in `Poetic-Poems/poetic`, check whether `lib/labels.sh` is similarly mirrored before editing (it is not one of the td-tooling files, so it should be editable here).

Noticed by the Approver while judging PR #919 (issue #876), which introduced R12's reliance on the label's presence in the repository under review.
