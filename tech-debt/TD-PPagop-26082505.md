title: "An already-settled open question resurfaces in every later adjudication pass and escalation body for the same pull request"
status: open
filed: 2026-08-25
---

**What.** `landing_open_question_latest` (lib/landing.sh) returns every `open-question-raised` question ever logged for a pull request, deduplicated by text but with no filter at the last `settled` `open-question-adjudication` event. After question A is settled and the label released, a later Reviewer round raising question B re-projects the label and hands the next adjudication pass — and any escalation issue body — both A and B.

**Why it matters.** `prompts/approver-adjudicate-open-question.md` tells the adjudicator that `questions` contains only questions 'not yet settled or escalated' (untrue in this scenario) and instructs it to `escalate` the whole pass if even one question does not settle — so a stale, already-answered question can drag a pass to escalate and be listed in the escalation issue as though open. The failure direction is safe (toward a human, never a wrong landing) but costs a confused escalation issue and a wasted bounded pass. Relatedly, the warning logged when a settled adjudication cannot remove the label (`_landing_open_question_resolve`, agent-cycle.sh) claims the question 'will settle again next round', but `open_question_adjudicated_before` counts the settled event, so the next round escalates without adjudicating — the warning text is wrong about the mechanism it names.

**Where.** lib/landing.sh (`landing_open_question_latest`), agent-cycle.sh (`_landing_open_question_resolve`, `run_open_question_adjudication`, `open_question_escalate`), prompts/approver-adjudicate-open-question.md, docs/IMPLEMENTATION-PIPELINE-SPEC.md requirement 8f, test/landing.test.sh and test/open-question-adjudication.test.sh.

**Suggested fix.** Add a high-water mark: filter the union at the timestamp of the last `settled` `open-question-adjudication` for the pull request (the union-across-rounds behaviour below that mark is deliberate and argued in the function's own header — keep it). Correct the prompt sentence and the release-failure warning to match, and update requirement 8f's acceptance check and the two test files' assertions.
