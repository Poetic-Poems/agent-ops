**Severity:** Low

`costWindowControl()` in `dashboard/index.html` builds a `<label>` as a
plain sibling of its `<select class="costwindow">`, not wrapping it, with
no `for`/`id` pair — unlike the auto-refresh checkbox elsewhere in the same
file, correctly nested. Separately, no document catalogues what personal or
sensitive data the pipeline touches, stores, or retains (GitHub usernames,
PR/issue text, retention periods governed by `cycles_retained` /
`log_retained_bytes` in `config.json`).

The select's label gap is a small, easily-missed inconsistency against a
pattern used correctly elsewhere in the same file. The data-inventory gap
exists because the audience has been one operator processing already-public
data, where the question has not yet been forced.

**Ongoing cost:** low in both cases today — the select's mislabeling is a
minor screen-reader annoyance, and the data touched is already public
GitHub metadata for a single-operator audience. The data-inventory gap will
matter more once `docs/ROADMAP.md`'s multi-tenant generalisation proceeds
to act on other organisations' repositories.

**Suggested fix:** wrap the `<select>` in its `<label>` (or add a matching
`for`/`id`); add a short data-inventory section (in README.md or a new
`docs/DATA-HANDLING.md`) stating what's read, stored, for how long, and
where, ahead of onboarding any non-Poetic-Poems installation.
