title: "check-node-compose.sh does not audit the reconciler's own wiring, so a node whose reconciliation is silently off still passes every host-side check"
status: open
filed: 2026-09-11
---

`scripts/check-node-compose.sh` is the host-side audit of what no container
can see: the stack's `compose.yaml` against the running image's copy, the
mount that arms the in-container drift check, the watchtower pre-update label
on every container, and watchtower's actual environment. Requirement 2.5a
added a second delivery mechanism to a node — the `reconciler` service — with
two host-shaped preconditions that script does not check: that
`AGENT_OPS_PROJECT_DIR` actually names this stack's directory (a node that
copied its `.env` from the stack beside it points the reconciler at its
neighbour's file), and that `DOCKER_GID` matches this host's docker group (a
wrong id leaves the container unable to open the socket it holds).

Both failures are visible — the reconciler records `refused` or a docker
permission error in its verdict, and that verdict reaches every dashboard —
so nothing is silent at the fleet level. What is missing is the host-side,
before-the-fact check that the rest of this file's properties get, which is
the one an operator runs after a bring-up or a stack move and the one that
would catch a wrong `AGENT_OPS_PROJECT_DIR` before it reconciles the wrong
directory.

Suggested fix: two more checks in `check-node-compose.sh` — that the
`reconciler` container's project-directory bind mount (`docker inspect`)
resolves to `$stack_dir`, and that `DOCKER_GID` in `.env` matches
`getent group docker` on this host — both read-only, both alongside the
existing label and watchtower-environment checks, and both covered in
`test/check-node-compose.test.sh` against its stubbed `docker`.

Noticed while building the reconciler (the pull request adding requirement
2.5a).
