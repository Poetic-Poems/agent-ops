`item_live_text` (lib/candidate-select.sh) builds an issue's live text with `gh issue view --json body,comments`, but gh's GraphQL layer fetches only the first ~100 comments for `--json comments` and does not paginate. Requirement 17g and the function's own header say the live text is the body "plus every comment"; past the ceiling that is not what is fetched. Two consequences on a long thread: (1) an honest `acceptance` backtick span quoting a comment past the ceiling would fault as `fabricated` — a mislabelled hard skip (safe direction, wrong telemetry); (2) `item_text_supply` would append a silently truncated thread under the heading "Live item text (supplied verbatim by the Script)" — a Script-authored completeness claim the Implementer is told to trust, which is the same over-trust class requirement 17g exists to close. No thread in the fleet's repos approaches 100 comments today, so this is a recorded edge, not an active defect. Suggested fix: fetch comments via `gh api --paginate repos/<repo>/issues/<n>/comments --jq '.[].body'` (joined after the body) instead of `--json comments`, and extend test/item-text-fabrication.test.sh's mocked `gh` to pin the paginated call shape. Noticed while approving PR #825 (requirement 17g, issue #821).
