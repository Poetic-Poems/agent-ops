What: dashboard/index.html (~lines 2879-2929) computes humanQueueN as every ready non-CHANGES_REQUESTED labelled PR and excludes it from the back-pressure gauge's trip sum, with no read of merge_autonomy_effective_level. But requirement 2.2's real gate has been level-aware since D18 WI-6: at agent-merges-routine and above nothing is excluded — agent-cycle.sh resolves backpressure_autonomous_rank and zeroes n_human per repo, so every ready PR counts. Why it matters: on the most autonomous repos the gauge under-reads against the cap exactly where the cycle's own count trips, so the dashboard shows an open gate while the fleet is standing down; the card's 'waiting on human' tooltip bucket also misnames the population at those rungs, and DASHBOARD-SPEC.md's back-pressure card section (~lines 840-856) says the card mirrors 'the same split the cycle logs', which is no longer true at agent-merges-routine+. Where: dashboard/index.html gauge block; docs/DASHBOARD-SPEC.md back-pressure card section; scripts/publish-dashboard.sh (the data feed). Suggested fix: publish each repo's effective merge-autonomy level with the dashboard data (publish-dashboard.sh already reads config and state), have the gauge count every ready PR for repos at agent-merges-routine and above — mirroring agent-cycle.sh's branch — and update the card's spec section and tooltip wording in the same change. Found while reviewing PR #748's vocabulary sweep; pre-existing, not that PR's defect.
