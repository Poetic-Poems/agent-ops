The dashboard's provider-unreachable badge (issue #1073, docs/DASHBOARD-SPEC.md) renders whenever the newest crash_loop_verdict run over the union log has escalate: false, and that run only ends on a Co-Ordinator stage-end exit 0. A fleet that stops running the Co-Ordinator entirely (every node disabled, or stood down) after a transient run leaves the badge lit against its last-known timestamps until log rotation drops those lines — the one case where DASHBOARD-SPEC's 'renders nothing the moment no such run is currently active' does not describe what a viewer sees as current. Mitigations already in place: the tooltip carries fmtAgo(last_ts) so the run reads as old, and a halted node is stale-badged anyway. The Reviewer raised this on agent-ops#1077 and left it for a human; recording it here so it survives the merge. Fixes: (a) bound the badge's rendering in scripts/publish-dashboard.sh or dashboard/index.html by an age threshold on the verdict's last_ts, reusing an existing staleness constant; or (b) amend DASHBOARD-SPEC.md to state the halted-fleet persistence explicitly and bless it.

## Default: Option (a), an age bound on last_ts reusing an existing staleness threshold — it keeps the badge honest without a spec carve-out for a misleading edge case.
Noticed while the Approver was judging https://github.com/Poetic-Poems/agent-ops/pull/1077.
