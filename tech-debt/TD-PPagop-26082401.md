agent-ops#734 fixed the Reviewer stage's own exposure to the Bash tool's
10-minute per-command ceiling: a command still running there is killed and
returns no output at all, so a single unbatched `test/*.test.sh` run (140
files) risked losing the whole test evidence — and, on PR #729, the whole
review — to a wall nothing in the prompt had ever named. The fix
(`scripts/run-tests.sh --list`, `prompts/reviewer.md`'s new ceiling
documentation and batching instructions, requirement 29a in
`docs/IMPLEMENTATION-PIPELINE-SPEC.md`) is scoped to the Reviewer, per that
issue's own framing and acceptance criteria.

The Implementer runs the identical suite under the identical constraint.
Requirement 24 (`prompts/implementer.md` step 4, "Verify like CI does") has
it "run the same lint/typecheck/format/test/build commands the repo's CI
workflows run" — when the repo under work is agent-ops itself, that is the
same 140-file `test/*.test.sh` suite, run by the same one-shot,
no-resumption stage (requirement 21), through the same Bash tool with the
same ceiling. Nothing about the Implementer's own prompt or the spec's
requirement 21/24 currently says so, and nothing stops an Implementer from
hand-rolling the same unbatched loop that burned the Reviewer's budget.

## Suggested fix

Extend `prompts/implementer.md`'s "Long-running commands" section with the
same ceiling paragraph `prompts/reviewer.md` now carries (or a shared
cross-reference, if the two prompts gain a mechanism for that), and add the
same batching instruction to step 4 ("Verify like CI does") for this repo's
own suite: list via `scripts/run-tests.sh --list`, batch into groups sized
to clear the ceiling, run one `scripts/run-tests.sh <group>` per group. Add
the matching spec requirement (a 24c, following the numbering already used
for step 4's sub-requirements) mirroring 29a.

Not fixed alongside agent-ops#734 itself, to keep that pull request scoped to
what its own issue and acceptance criteria asked for.
