Issue #653 (Phase-1 audit item 1) reworded the 'Both target repos'/'either repository' phrasing in `prompts/coordinator.md`, `implementer.md`, `project-reviewer.md` and `reviewer.md`, but the same class of phrasing — implying exactly two configured repositories where `repos[]` and `project_review.repos` are arbitrary-length — survives untracked elsewhere: `prompts/enabler.md:135` ('Items may come from either repository') and `:141` ('reads across both repositories'); `docs/IMPLEMENTATION-PIPELINE-SPEC.md:18` ('one of two GitHub repositories'), `:84` ('both target repos') and `:598` ('Conventions shared by both repos'); `docs/REVIEW-PIPELINE-SPEC.md:875` ('Create the review label in both repos'); README prose at lines 130, 811, 1112, 1592 and 2139; and `config.schema.json:600`, whose `x-docs.readme` text 'across both repos' renders into README's generated config-table row for `max_open_agent_prs` (fix it in the schema and re-run `scripts/render-config-table.sh`, never in the README row). No open issue or tech-debt record covers these — the audit's item 1 and #653 scoped only the four prompt files. Suggested fix: one prose sweep mirroring #653 across `prompts/enabler.md`, the two specs, README, and the schema description, keeping the specs as-built (they should describe the configured, arbitrary-length repo set, which is what the code implements).

Noticed while the Approver was judging https://github.com/Poetic-Poems/agent-ops/pull/716.


Migrated to https://github.com/Poetic-Poems/agent-ops/issues/958.
