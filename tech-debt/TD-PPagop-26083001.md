lib/enabler.sh's new enabler_decision_comment (agent-ops#936/#1049) says in its own docstring that 'a failure here is logged as a warning, never a reason to unwind the verdict', but when the gh issue comment call fails it only writes stderr to $cycle_dir/enabler-decision-comment.err and returns empty — the caller logs decision-taken without comment_url and emits no warning event, and the thread-reconcile branch for a decide verdict deliberately posts nothing on the assumption the decision comment already posted. On a transient gh failure the item is unblocked with the decision recorded only in the fleet log, while the issue thread still shows the ordinary Enabler's 'an escalation is being requested' note with neither a decision comment nor a correction. The decision itself is not lost (decision-taken and decisions_map still carry it), so this is visibility-only, but it is exactly the misdescribed-corner shape this PR's own review round dinged elsewhere. Suggested fix: on an empty return from enabler_decision_comment, log_event a warning naming the item, and either retry the post next cycle or fall through to escalation_thread_reconcile with a decide-settled-style correcting comment; align the docstring with whichever behaviour is chosen.

Noticed while the Approver was judging https://github.com/Poetic-Poems/agent-ops/pull/1049.
