title: Bounded-today fleet-state JSON still travels to jq in argv at several sites

Requirement 4g moved the unbounded fleet-state aggregates — the void extract,
the blocked extract, the refinements map, the claims array and the pre-fetched
repo array — onto `jq`'s stdin at the sites where the 2026-08-12 argv-cap
outage actually bit: the no-op fingerprint and Co-Ordinator input builds
(fatal, exit 126 before the Co-Ordinator on every node), the act-on-void
sweep, the register-void pass and the unvoid-label read (silent `[]`
degradation). The sites below still deliver JSON via `--argjson`. Each input
is bounded *today* — by the set of open blocks, live claims, or one repo's
pre-fetch — but several are one growth curve away from the same
`MAX_ARG_STRLEN` (131072-byte) failure, and every guarded one fails silent,
not loud: the blocked extract already measures ~40 KiB across 47 entries,
because block entries carry their evidence payloads.

- `lib/work-gone.sh` `work_gone_clearances` — `--argjson blocked` (the open
  blocked set) and `--argjson states`; past the cap it degrades to `[]` and
  demonstrably-finished blocks silently stop clearing.
- `lib/refinement.sh` `refinement_hand_flag_new` and
  `refinement_hand_flag_cleared` — `--argjson b "$blocked"`; hand-applied
  refinement flags silently stop being noticed or cleared.
- `lib/label-marker.sh` `label_filter_own_applications` and
  `label_own_stale_applications` — candidates, own-actions map, kept set and
  blocked set all in argv; the fail-safe direction differs per function by
  design, so a silent overflow changes behaviour asymmetrically.
- `agent-cycle.sh` `exclude_claimed_prs` / `exclude_claimed_items` — the
  claims arrays; past the cap the candidate array passes through unfiltered,
  reopening exactly the claimed-work proposals #305 closed.
- `agent-cycle.sh` repo-gather appends (`--argjson e "$entry"` and the
  `--argjson s "$state"` / unvoid-request / hand-flag accumulators around it)
  — `$entry` is one repo's pre-fetched sources *including whole issue
  threads* (requirement 3d/#118) and, since requirement 3t/#310, that repo's
  whole open tech-debt register too (measured at gather time: 10 items /
  35 KB for `agent-ops`, 15 / 38 KB for `poetic`), the least bounded of this
  list.
- `scripts/gather-tech-debt.sh`'s per-item array append (`--argjson e
  "$entry"`, requirement 3t) — one register item file per call, so a single
  item file past the cap degrades that repo's *entire* `tech_debt` array to
  `[]` via the script's `degrade` path. Loud on stderr, unlike the rest of
  this list, but the Co-Ordinator still sees an empty band rather than a
  failure.
- `agent-cycle.sh` Enabler/Refiner engagement input builds (`--argjson items
  "$claimed_json"`) — bounded by the per-engagement caps.
- `lib/cycle-state.sh` `enabler_eligible_items` — `--argjson open
  "$open_issues"`, one number per open issue per repo.

The fix is the mechanical conversion requirement 4g specifies: concatenate
the documents (`docs="$a"$'\n'"$b"`), deliver with a here-string, bind
positionally with `input as $name` in the printed order, and leave only
configuration-bounded values in argv. Convert a site together with the test
that pins its fail-safe direction, as `test/unvoid-label.test.sh`'s
oversized-void case does, so the conversion cannot flip a fail-open site to
fail-closed or vice versa.
