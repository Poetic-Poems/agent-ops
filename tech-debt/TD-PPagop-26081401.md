TD-PPagop-26081301 converted every `--argjson` delivery site it enumerated to
requirement 4g's stdin delivery. The sites below were not on its list and are
still in argv, and each carries fleet state rather than the
configuration-bounded values requirement 4g permits there (a model name, a
config object, a prompt sha, one repo's register ids). None is near
`MAX_ARG_STRLEN` (131072 bytes) today; they are recorded here because
TD-PPagop-26081301 is now resolved, so without this record the residue is not
written down anywhere.

They are listed loudest-failure-first, since that is the order in which they
are worth converting:

- `scripts/gather-merge-conflicts.sh`'s per-candidate array append
  (`--argjson c "$cand"`) is the one whose input is genuinely unbounded rather
  than merely growing: the candidate carries `body: ($pr.body // "")`, a whole
  pull-request body, which nothing in this system caps. The append is
  unguarded, so past the cap the script dies under `set -e` and the repo's
  whole `merge_conflicts` band is lost — loud, at least, unlike most of this
  list.
- `agent-cycle.sh`'s per-repo claims fold (`--argjson items
  "$repo_claimed_json"`, requirement 3o) delivers the claims array — one of the
  five aggregates requirement 4g names by name as growing with the fleet's
  history — in argv. Unguarded, so it fails the cycle loudly rather than
  silently, which is the only reason it is not first here.
- `agent-cycle.sh`'s verdict-contradiction logging (requirement 3v) passes
  `--argjson items "$unaccounted_json"` at four call sites — the unaccounted
  eligible items, carried whole out of the pre-fetched bands. Past the cap the
  Script would lose the very event that records a Co-Ordinator contradiction,
  which is the record the crash-loop ladder and the dashboard read.
- `scripts/gather-hand-flagged-refinements.sh`'s per-item array append
  (`--argjson e "$entry"`) is the exact shape TD-PPagop-26081301 converted in
  `scripts/gather-tech-debt.sh`, left behind only because it was not on that
  item's list.
- `lib/work-gone.sh` `work_gone_clearances` still takes `--argjson register`,
  `--argjson review` and `--argjson plan`. TD-PPagop-26081301 converted this
  function's `blocked` and `states` arguments and named only those two, so
  these three side-channel status maps stayed in argv; each holds one short
  entry per blocked item of its class, so they are the smallest thing on this
  list, but they still grow with the blocked set rather than with
  configuration.
- `agent-cycle.sh`'s Enabler and Refiner claim accumulators (`--argjson e
  "$entry"`, the loops that build `claimed_json`) deliver one blocked entry
  each, evidence payload included.
- `agent-cycle.sh`'s two unparseable-verdict warnings (`--argjson items
  "$items_named_json"`) deliver a list trimmed to `{repo, item}` — the most
  bounded of this list, and included only so the sweep is complete.

The fix is the same mechanical conversion at each: concatenate the documents
(`docs="$a"$'\n'"$b"`), deliver with a here-string, bind positionally with
`input as $name` in the printed order. Convert a site together with a test
that pins its fail-safe direction past the cap, as requirement 4g's own
acceptance check now requires and as `test/work-gone.test.sh`,
`test/pr-claim-exclusion.test.sh` and their siblings do for the sites
TD-PPagop-26081301 converted.
