**What:** `_landing_stage_attempt` fills the audit record's `approver.history` from `landing_approver_adjudication_history` reading `${log_file:-}` on the round that first approves a pull request (agent-cycle.sh:4590), and `$union_log` only on a 2.1e retry re-arm — a convention copied from `landing_retry_tier`, and codified in requirement 8x. **Why it matters:** the field claims to be 'this pull request's full adjudication history — every approver-verdict event this pull request ever received', but a refuse streak whose earlier engagements ran on a peer node leaves those refusals only in the peers' logs; the local log.jsonl (never rotated, so complete for *this* node) silently omits them, and the record then understates exactly the history that matters most — a contested landing's. **Where:** agent-cycle.sh:4586-4592, lib/landing.sh's `landing_approver_adjudication_history` header, docs/IMPLEMENTATION-PIPELINE-SPEC.md requirement 8x. **Suggested fix:** `run_landing_stage` is invoked at agent-cycle.sh:9685, well after the fleet union log is built (line 6381), so `union_log` is available on the first-approval path too; read `${union_log:-$log_file}` there and additionally scan the tail of the local log_file for events written after the union snapshot (the same tail-append pattern lines 6826/7389 already use), so the just-written approver-verdict of this round is never missed. Alternatively, narrow requirement 8x's wording to 'every approver-verdict this node's own retained log holds' so the record never claims more than it reads. Test coverage should include a history seeded only in union_log (a peer's refusal) plus this round's verdict in log_file.

Noticed while the Approver was judging https://github.com/Poetic-Poems/agent-ops/pull/685.
