**Severity:** Medium

Noticed while reviewing PR #796 (requirement 2m, TD-PPagop-26082304), which
introduced the key.

Requirement 2m's `escalation_webhook_url` is the first configuration value in
this system whose *content* is a credential. A webhook URL for every common
target — Slack, Discord, Teams, PagerDuty, or a bare endpoint with no
signature check — is a bearer secret: possession of the URL is authorisation
to post to it, which is precisely why it works as an alarm channel a dead
`GH_TOKEN` cannot silence.

The only place the pipeline reads it from is `config.json`, and `config.json`
is:

- **tracked in this repository, which is public.** Setting the key as
  documented commits a live secret to a public repo, where it is in the
  history permanently and rotating it means rotating the endpoint.
- **fleet-wide, not per node.** It ships inside the image
  (`deploy/docker/README.md`: "They live in the image, so changing one is a
  pull request and an image roll, not an `.env` edit — which is the reason
  `CYCLE_MINUTE` exists as a per-node override at all"), so one value is
  every node's value. #796's original wording described the key as
  "node-local"; that was corrected during review, but correcting the
  description does not give the key the per-node channel it wants.

Every other credential this system uses comes from the environment —
`GH_TOKEN`, `PULLWRIGHT_APPROVER_APP_ID`, the Approver App's private key —
never from `config.json`. So the one key whose value is a secret is the one
key with no environment path, and it points the opposite way from the
convention around it.

## Why it matters

It is the difference between requirement 2m being landable and being
*switchable on*. As shipped the key defaults to empty and the whole path is a
no-op, so nothing regresses — but an operator who wants the alarm TD-PPagop-26082304
was filed to get has no safe way to configure it. The natural workaround
(commit the URL, accept the exposure) is worse than the gap it closes, and
the other one (keep it unset) leaves the original debt's own consequence
untouched.

There is a ready-made place for it. Enabling the webhook already requires a
per-node `.env` edit for a *different* reason — the webhook's host must be in
that node's `EGRESS_EXTRA_ALLOW` or the egress fence answers every POST with
a `403` (requirement 2m, added in #796) — so the operator is editing `.env`
regardless. Putting the URL beside the allowlist entry costs them nothing
extra and solves both the secrecy and the per-node problem at once.

## Where

- `config.schema.json` — the `escalation_webhook_url` key.
- `agent-cycle.sh` — where the key is read (`escalation_webhook_url="$(cfg
  '.escalation_webhook_url')"`), which is the single line an environment
  source would change.
- `deploy/docker/compose.yaml` — the scheduler's environment block, where a
  new `.env`-sourced variable would be passed through, alongside
  `EGRESS_EXTRA_ALLOW`'s own plumbing.
- `docs/IMPLEMENTATION-PIPELINE-SPEC.md` requirement 2m; `README.md`'s
  configuration table (generated — edit the schema).
- `scripts/doctor.sh` — whichever shape wins should be checked there the way
  `approver_app_id` is cross-checked against its environment counterpart, or
  a misconfigured node discovers it only when an escalation fails to file.

## Suggested fix

Give the key an environment source and let `.env` be where the secret lives.
The smallest shape is an override — `ESCALATION_WEBHOOK_URL` from the
environment wins over the `config.json` value, so an installation can leave
the key unset in the tracked file entirely — passed through in
`compose.yaml`'s scheduler environment like the proxy variables already are.
Two alternatives worth weighing before picking: an `escalation_webhook_url_env`
key naming the variable to read (explicit, and keeps `config.json` the single
declaration of what is configured), or a path key pointing at a file inside
the state volume (fits a node that has no `.env` control).

Whichever wins, the schema's `^$|^https://` pattern check currently applies
only to the `config.json` value; an environment-sourced value needs the same
validation, or the pattern stops being the enforceable statement the config
table claims it is.
