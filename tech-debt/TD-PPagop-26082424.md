title: An unreconciled comment on a Ready pull request refuses landing every cycle, and no source routes it to an Implementer round
status: open

Gate 4 of `_landing_stage_attempt` (`agent-cycle.sh`) now refuses to arm a
pull request carrying an unreconciled human comment posted since it last left
draft (agent-ops#672). That is the right refusal — it is the human veto D18
promises — but nothing downstream turns the refusal back into work, so the
pull request stalls rather than getting the comment answered.

Every other permanent refusal reason has a route back. "A human
`CHANGES_REQUESTED` stands" is refused here *and* selected by
`scripts/gather-review-feedback.sh` as a `review-feedback` candidate, so an
Implementer answers the review and a Reviewer cites it. The new reason has no
such route:

- `gather-review-feedback.sh` requires `reviewDecision == CHANGES_REQUESTED`
  and a non-draft pull request. A plain comment produces neither, which that
  script's own header states outright ("this source structurally cannot see
  the change request PR #512 carried"), deferring the case to requirement
  31c's reconciliation gate — correct when that gate ran only at hand-off,
  where the Reviewer could push the fix itself, and no longer sufficient now
  the same definition also gates arming, long after any Reviewer session has
  ended.
- `scripts/gather-abandoned-drafts.sh` sees only drafts; this pull request is
  Ready.
- Nothing reads `landing-refused` events. `scripts/publish-dashboard.sh`
  does not surface them, and no sweep escalates a repeated one, so the
  refusal costs one log line per cycle, indefinitely, that nobody reads.

The nearest thing to a signal is `scripts/sweep-human-visibility.sh`'s idle
nudge (requirement 38c), and it is actively misleading here: it fires on an
approved, green, mergeable pull request and tells the assignee it "is waiting
on a merge click", when in fact the pipeline is refusing to land it over that
person's own comment. It also fires once — its `<!-- agent-ops:human-nudge -->`
marker suppresses repeats — so the one message anyone gets says the wrong
thing.

**Suggested fix**: give the case a route. The most direct is a candidate
source for "a pull request whose landing is refused for an unreconciled
comment", sharing `lib/reconciliation-gate.sh`'s definition (requirement 34a:
one definition per rule computed twice), handing the Implementer the comment
prose verbatim exactly as `review-feedback` does — which also gets the
`<!-- agent-ops:reconciles comment=<id> -->` citation written, clearing the
gate on the next cycle. Widening `gather-review-feedback.sh`'s own candidate
rule is the other option and its header argues against it, but the argument
it makes is about the hand-off case, not this one, so it deserves re-reading
rather than assuming. Worth deciding at the same time: whether the idle
nudge should name the real reason when a `landing-refused` for this pull
request stands, rather than claiming it waits on a merge click.

Noticed while reviewing PR #745 (agent-ops#672), which introduced the
refusal.
