entrypoint.sh warns on every container start when $CLAUDE_CONFIG_DIR/.credentials.json is absent: 'no cycle can run until this node is authenticated once: docker compose exec scheduler claude'. Since PR #856 (issue #684) documented the BYO API-key path as D4's primary, that message is false on that path — a node with ANTHROPIC_API_KEY set and no OAuth login runs cycles fine, yet is told on every start that it cannot, immediately after deploy/docker/README.md step 4 said there was 'nothing further to do'. An adopter following the primary path is steered into an unnecessary interactive OAuth login. entrypoint.sh was outside issue #684's named scope (only deploy/docker/.env.example, compose.yaml, README.md and scripts/doctor.sh), and TD-PPagop-26082818 covers only the top-level README's framing, not this runtime message. Suggested fix: in the .credentials.json check in deploy/docker/entrypoint.sh (~line 64), suppress the warning — or reword it to name the API-key path the node is actually on — when ANTHROPIC_API_KEY is non-empty, and update the as-built spec's node-stack section to match.

Noticed while the Approver was judging https://github.com/Poetic-Poems/agent-ops/pull/856.
