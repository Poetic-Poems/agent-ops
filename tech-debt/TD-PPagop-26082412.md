**Severity:** Medium

`deploy/docker/Dockerfile` pins and checksum-verifies `supercronic` and
`shellcheck` (binaries not available from a signed apt repository), but
installs OS packages (`jq`, `curl`, `python3`, `perl`, `git`, etc.) via
unpinned `apt-get install -y`, and installs the `claude-code` npm package
via `ARG CLAUDE_CODE_VERSION=latest` — deliberately unpinned per the
adjacent comment, on the reasoning that CI rebuilds the image on every
merge.

The pinning discipline was applied where a specific incident or concern
prompted it (binaries with no package-manager-provided integrity check);
OS packages and `claude-code` were left floating because the "CI rebuilds
often" argument seemed sufficient at the time.

**Ongoing cost:** two builds of the same commit, days apart, can produce
different images if Ubuntu ships a security update to an OS package, or
Anthropic publishes a new `claude-code` release, in between — undermining
the reproducibility the image-as-artefact deployment model
(`docs/ROADMAP.md` D16) otherwise relies on. `claude-code` specifically is
the dependency with the deepest reach (same tool/token access as
TD-PPagop-26082407) — a bad release reaches every subsequently-built node
with no local pin to fall back to.

**Suggested fix:** pin `claude-code` to a specific major/minor version,
bumped deliberately in its own PR; either pin the base image to a specific
digest or document the OS-package layer as an intentional, reasoned
trade-off in the Dockerfile's own comments.
