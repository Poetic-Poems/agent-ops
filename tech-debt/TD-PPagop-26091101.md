`monitor-cycle.sh` (agent-ops#1284) writes one report per day to
`state_dir/monitor/<date>/report.md` and records the whole run — the filings
ledger and the page triage included — on its `monitor-report-written` event in
`monitor-log.jsonl`. Both replicate fleet-wide by the ordinary state-sync push,
and neither reaches `dashboard/index.html`: the only trace of a monitor run on
the page today is the `monitor` row in the Stage health panel (which says the
pipeline ran, not what it found) and whatever the run filed as a GitHub issue.
So the one artefact the pipeline exists to produce is readable only by opening a
file in `state_dir`, on a node — which is exactly the "self-certification"
posture agent-ops#1286's viewer-vantage probe exists to distrust, and it makes
the daily reading invisible to the audience most likely to act on it.

This is the same scope boundary `docs/REVIEW-PIPELINE-SPEC.md` R17 draws for the
review pipeline's own reports, and it is deferred here for the same reason: the
dashboard has its own as-built spec (`docs/DASHBOARD-SPEC.md`), and surfacing a
new artefact is a change to the Publisher's payload and the Site's panels, not to
the pipeline that produced it.

Suggested fix: have `scripts/publish-dashboard.sh` fold the newest
`monitor-report-written` event from the fleet union of `monitor-log.jsonl` into
its payload — the date, the trigger, the report path, `findings_stated`,
`findings_filed` and the ledger rows — and render a Monitor panel beside the
Stage health one: the day's headline counts, the ledger as a table with each
filed finding's issue linked, and the page-triage verdicts. Carry the report's
own Markdown only if the payload can afford it; the ledger plus links is most of
the value. Update `docs/DASHBOARD-SPEC.md` and
`docs/MONITOR-PIPELINE-SPEC.md` M16 in the same change, and extend
`test/publish-dashboard.test.sh` and `test/dashboard-render.test.sh`.

Noticed while implementing agent-ops#1284 (the Pipeline Monitor); the issue's own
acceptance names the stage-health verdict on the dashboard, which this change
delivers, and says nothing about the report, which it does not.
