title: "The vendored project-review skill now files debt only as `pw::type:tech-debt` issues, with no arm for a project that has no GitHub remote or no such label"
status: open
filed: 2026-08-29
---

**What.** The vendored `project-review` skill
(`.claude/skills/project-review/SKILL.md` Step 0.3 and Step 4 "Tech debt",
`references/output-templates.md`'s "Tech debt" section), as rewritten by
agent-ops#876, files every item of new debt with `gh issue create --label
pw::type:tech-debt` and forbids the two fallbacks it used to have: "never as
a register file, whether or not the project has a register in either format
below, and never by inventing a register where none exists". The only
alternative arm it states is scoped to one environment — "In the Claude.ai
chat, where GitHub is not directly reachable, list each item that would be
filed … in the summary presented to the user instead". A review run under
Claude Code or Cowork against a project with no GitHub remote, or hosted
somewhere other than GitHub, therefore reaches Step 4 with `gh issue create`
having no target and every other destination closed to it, and the skill
says nothing about what to do. The same hole opens on a GitHub-hosted
project outside the Poetic fleet: `pw::type:tech-debt` is a
Poetic-namespaced label, and nothing in the skill creates it or falls back
when `gh issue create --label` fails because it does not exist.

**Why it matters.** The skill is documented for arbitrary projects — its
description is "review of a software project", it is manually invoked by a
user, and its own "Environment-Specific Operating Conditions" promise
Claude Code / Cowork only "full shell and repository access", never a
GitHub remote. Inside the pipeline the assumption always holds, because
`review-cycle.sh` only ever reviews GitHub repositories in
`project_review.repos`; outside it, the tech-debt half of the review's
output is simply lost, and quietly — the report set still looks complete,
which is exactly the failure mode `docs/REVIEW-PIPELINE-SPEC.md` acceptance
check 8 was written to catch for the cross-reference.

**Where.** `.claude/skills/project-review/SKILL.md` (Step 0.3; Step 4 "Tech
debt") and `.claude/skills/project-review/references/output-templates.md`
("Tech debt"). The pipeline-side requirements this implements —
`docs/REVIEW-PIPELINE-SPEC.md` R12/R12a — are correct as they stand: they
bind only repositories `review-cycle.sh` reviews, all of which are on
GitHub.

**Suggested fix.** Decide which the skill is, and say so in one place:
either (a) declare it GitHub-only for the tech-debt step and state that
plainly in "Environment-Specific Operating Conditions", so a user reviewing
a non-GitHub project knows before Step 4 what they will not get; or (b)
restore a stated fallback for "GitHub not reachable, repository writable" —
the per-item register the skill used to create — decoupled from the
Claude.ai-chat arm it is currently welded to. Either way, say what to do
when the label does not exist in the target repository (create it, or file
unlabelled and tell the user), since that is a separate failure from having
no remote at all.

Distinct from TD-PPagop-26082904, which records the same label's absence in
a *Poetic* repository configured for review but not for the implementation
pipeline (a `lib/labels.sh` `labels_catalogue` gap, fixed in the catalogue);
this item is about the skill's own instructions having no arm at all when
GitHub or the label is out of reach, including outside the fleet where the
catalogue never runs.

Noticed while reviewing https://github.com/Poetic-Poems/agent-ops/pull/919.
