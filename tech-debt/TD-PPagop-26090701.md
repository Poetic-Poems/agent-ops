Issue #958 (PR #1206) swept the fixed-count 'both/either repo' phrasing from its enumerated locations, and its acceptance grep ('both repos', 'both target repos', 'either repositor') now comes back clean — but two instances of the same class survive because neither matches those terms: README.md:2378, 'Both repo's CLAUDE.md files bind all work done inside them' (the apostrophe defeats the 'both repos' term, and 'repo's' is also a grammar error for 'repos''), and docs/IMPLEMENTATION-PIPELINE-SPEC.md:11, 'follow the conventions of the two target repositories', three lines above a location #958 did fix. Both imply exactly two configured repositories where repos[] is arbitrary-length — the exact defect class #653 and #958 existed to remove, surviving untracked the same way #958's own locations survived #653. Fix: reword both in place following the established pattern (e.g. 'the target repos'' / 'the configured target repositories'), prose only, no behavior change. Nearby 'two repositories' phrasings that are genuinely about the current installation (IMPLEMENTATION-PIPELINE-SPEC.md:571 explicitly describes 'this installation's current config.json') or about as-built behavior (the review-lock doubling at :6031) are correct as-built and out of scope.
