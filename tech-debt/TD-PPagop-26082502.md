title: The Autonomous landings panel's refusal-reason grouping is garbled by any reason string that embeds a colon before its own class prefix
status: in-progress
filed: 2026-08-25
---

`docs/DASHBOARD-SPEC.md`'s refusal-grouping note describes the class as "the
`reason` text before its first `:`" (`byReason`, `dashboard/index.html`),
and the intended examples — `ineligible:`, `unknown:`, `kill-switch:`,
`open-question:` — all put that prefix at the very start of the string, so
the rule works exactly as documented for them.

It does not work for every reason `_landing_stage_attempt` (`agent-cycle.sh`)
actually produces. Several gates compose a whole sentence with no
class-prefix convention at all, and some of those sentences embed a pull
request URL — which itself contains `:` (`https://…`) — before any
meaningful word boundary. `key = reason.split(":")[0]` then grabs the wrong
substring. Concretely, from the current `_landing_refuse` call sites:

- `could not read $pr_url's own review list to confirm the Approver's review
  actually landed` groups under `"could not read https"`, not a class naming
  what actually failed.
- `landing_arm could not enqueue or auto-merge $pr_url: …` groups under
  `"landing_arm could not enqueue or auto-merge https"`.
- `could not read $pr_url's own labels to confirm no open question stands`
  (requirement 8f, agent-ops#668) has the same shape.

None of these is wrong in the sense of hiding a refusal — the panel still
counts it and still shows the full reason text somewhere a human can read —
but the grouping the panel's own justification ("two beside forty is a
classifier holding the line; two beside none may be a gate not running at
all") depends on is silently defeated for this whole family: each distinct
`$pr_url` produces its own one-off "group", so a real, repeated failure mode
(say, the Approver's review list becoming unreadable across many pull
requests) never accumulates into a visible count the way `ineligible ×12`
would.

**Suggested fix**: give every whole-sentence refusal in `_landing_stage_
attempt` the same `class:detail` shape the classifier-driven ones already
have (a short, GitHub-URL-free class word before the first `:`), rather than
leaving `dashboard/index.html`'s generic split to fend for itself against a
sentence structure it was never designed to parse. This touches every
`_landing_refuse` call site in `agent-cycle.sh`'s `_landing_stage_attempt`,
`docs/IMPLEMENTATION-PIPELINE-SPEC.md` requirement 8d's own reason-text
citations, and `test/landing-wiring.test.sh`'s `refusal`/`assert_contains`
assertions, which currently pin the exact sentences that would change.

Noticed while researching agent-ops#668 (PR #776) — not touched there since
the fix reaches well beyond that item's own scope.
