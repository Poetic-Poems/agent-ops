TD-PPagop-26081601 (agent-ops#473) added `timeout_approver` and
`inactivity_approver` to `config.schema.json`'s top-level keys, and
`approver` to `repos[].stage_timeouts`/`stage_inactivity`, so an
installation can now override either of the Approver's caps.

`scripts/doctor.sh`'s "Crontab" section carries its own, separate
enumeration of every `timeout_<actor>`/`inactivity_<actor>` key, used only
to warn an operator that setting one pins that cap and disables its
self-tuning:

```
[ "timeout_coordinator", "timeout_implementer", "timeout_reviewer",
  "timeout_enabler", "timeout_refiner", "inactivity_coordinator",
  "inactivity_implementer", "inactivity_reviewer", "inactivity_enabler",
  "inactivity_refiner" ]
```

`timeout_approver`/`inactivity_approver` are not in this list, so setting
either now passes schema validation (TD-PPagop-26081601's whole point) but
`doctor.sh` stays silent about it — the one place that is supposed to warn
an operator they have pinned a cap says nothing for this actor.

## Where

`scripts/doctor.sh`, the `jq` array a few lines above `section "Crontab"`
(search for `"timeout_coordinator"`).

## Suggested fix

Add `"timeout_approver"` and `"inactivity_approver"` to the array, in the
same position as the other four actors, and extend `test/doctor.test.sh`
with an assertion that setting `timeout_approver` warns, matching whatever
coverage exists for the other actors' pinned-override warning (if any).
