title: an empty merge_autonomy_protected_paths disables the protected-path landing gate with nothing reporting that it is off

`merge_autonomy_protected_paths` set to `[]` — at the top level or as a
`repos[]` override — resolves to an empty list rather than to the schema
default, and `_landing_is_protected`'s `any(.[]; …)` over an empty array is
false for every path. The protected-path gate then reports "nothing
protected was touched" for every diff in that repository, at every level,
and `landing_eligible` reads `eligible` where it would otherwise have
refused. `_escape_audit_protected_paths`
(`scripts/detect-classifier-escapes.sh`) resolves the same `[]` the same
way, so the post-hoc audit agrees and records no escape either.

`config.schema.json` constrains each entry to a non-empty string but sets no
`minItems` on either the top-level array or the `repos[]` override, so `[]`
is valid configuration and `agent-cycle.sh`'s schema gate passes it.

This is not a fail-open in the TD-PPagop-26082320 sense: an operator writing
`[]` has said "no path in this repository gates its own behaviour", which is
a legitimate statement for a repository that holds no pipeline code, and the
gate does exactly what was asked. What is missing is that it says so
*silently*. `scripts/doctor.sh` mentions `merge_autonomy_protected_paths`
nowhere, so the one consolidated autonomy-readiness verdict per repository
reports a repository at `agent-merges-routine` with its deadliest landing
gate switched off exactly as it reports one with the full nine-path default.
The same file already treats the neighbouring case as worth reporting:
`landing_cool_off_hours` resolving to `0` "disables D18 WI-12's own cool-off
control entirely" and earns a `warn` naming the repository and the level
(`scripts/doctor.sh`, D18 WI-12). An empty protected-path list is the same
shape of configured-off control with no such line, and it would reach a
reader only as an absence — no refusal, no event, nothing to grep for.

**Suggested fix.** Warn from `scripts/doctor.sh`, on the model of the
`landing_cool_off_hours 0` check: for each repository whose resolved
`merge_autonomy_protected_paths` is empty and whose resolved
`merge_autonomy` is `agent-merges-routine` or above, name the repository,
the level, and that no path can refuse a routine landing there. A
`minItems: 1` on the schema is the other option, but it forbids a choice an
operator may legitimately want, so the warning is the better shape. Whichever
lands, requirement 8d in `docs/IMPLEMENTATION-PIPELINE-SPEC.md` and
`test/doctor.test.sh` move with it, and the wording belongs in the schema's
own `description` for the key (a generated region — see `CLAUDE.md`), not
hand-written into the rendered tables.

Noticed while reviewing PR #733 (TD-PPagop-26082320), which hardened the
same helper's error contract against a malformed list without touching the
empty-list case.
