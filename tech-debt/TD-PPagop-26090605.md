id: TD-PPagop-26090605
title: "item_live_text's tech-debt branch reads a repo-content file path, predating the register's D15 issue migration"
status: open
filed: 2026-09-06
---

`item_live_text` (`lib/candidate-select.sh`) fetches a tech-debt item's live
text, for requirement 17g's own fabrication check, with:

```
tech-debt)
  gh api "repos/$repo/contents/tech-debt/${item}.md" --jq '.content | gsub("\n"; "") | @base64d'
  ;;
```

— treating `item` as a register filename (`tech-debt/<id>.md`) in the target
repository. That was correct before D15 (agent-ops#869/#875/#879 in this
repository's own numbering; the migration is fleet-wide, applying to every
target repository this pipeline operates on): a tech-debt item is now a
GitHub issue carrying the label `pw::type:tech-debt`, gathered by
`scripts/gather-tech-debt.sh` with `ref: (.number | tostring)` — a bare issue
number, never a register filename — and read the same way an `issues` entry
is (`gh issue view`, body plus every comment).

So this branch fetches the wrong path for every tech-debt item on a
D15-migrated target repository: `${item}.md` where `item` is a number like
`42` names a file that (almost always) does not exist, and the fetch fails.
Downstream, `item_text_fault`'s fail-closed contract
(TD-PPagop-26082307) turns that failure into a fault (`treated as fabricated
rather than assumed compliant`) rather than a successful check — the
opposite of silent, but still wrong: a tech-debt candidate this check
touches would be skipped for a defect in the check itself, not a real
fabrication, on every fitted cycle.

Not fixed in place here (noticed while implementing requirement 17h,
agent-ops#769's own pull request): that pull request adds `item_live_entry`
as a new, separate function reading tech-debt identically to `issues` (`gh
issue view`, matching `scripts/gather-tech-debt.sh`'s own shape) rather than
reusing or repairing this branch, specifically to avoid carrying this defect
into the new call site while leaving the existing one for a scoped fix of
its own. Per agent-ops#769's own tech-debt filing
(TD-PPagop-26090604), `item_text_fault`'s tech-debt path is itself now
unreachable in practice (every tech-debt candidate is composed by
requirement 17h before reaching it), so this fix has no observable urgency
until that dead code is either exercised again or removed — whichever
happens first should account for this file too.

Suggested fix: change `item_live_text`'s `tech-debt` branch to fetch the
same way `issues` does (`gh issue view "$item" --repo "$repo" --json
body,comments --jq '...'`), matching `item_live_entry`'s own tech-debt
handling (`lib/candidate-select.sh`) added by agent-ops#769. If
TD-PPagop-26090604 has already removed `item_text_fault`/`item_text_supply`
by the time this is picked up, confirm no other caller still depends on the
old file-path behaviour before changing it.
