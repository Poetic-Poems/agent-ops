D18 WI-7 (agent-ops#410, requirement 8d) arms landing exactly once, on the
round the Approver's own engagement reaches an explicit, non-adjudicating
`approve` (`run_landing_stage`, `agent-cycle.sh`). One of the gates it
re-reads fresh is `merge_budget_decide` (`lib/merge-budget.sh`): when the
repository's rolling-24-hour cap is already spent, the decision is `hold`,
`merge_budget_apply_decision` logs `merge-budget-hold` and the pull request
is left approved but unarmed — the design's own "the backlog queues
visibly" (§5.4).

## Why it matters

Nothing re-attempts a held pull request once the budget's own 24-hour window
rolls over and headroom reopens. `run_landing_stage` only ever runs once per
pull request, immediately after that round's own Approver engagement; there
is no later trigger that revisits an already-approved, already-`pr-ready`
pull request to ask "does the budget allow it now?" A human merging it by
hand is the only path left — visible through `merge-budget-hold` and the
WI-8 digest (#411, not yet built), but not automatic, which is easy to read
as a bug rather than the documented behaviour it is. `docs/reviews/2026-08-14-autonomy-investigation.md`
§5.4 and "## The Landing Gate" (`docs/IMPLEMENTATION-PIPELINE-SPEC.md`) both
say so explicitly as of this item's own filing, so this is deferred scope,
not an undocumented gap.

## Where

- `agent-cycle.sh` — `run_landing_stage` is the only caller of
  `merge_budget_decide`/`merge_budget_apply_decision`; nothing else in the
  pipeline reads a `merge-budget-hold` event back.
- `lib/merge-budget.sh` — `merge_budget_oldest_waiting` already names the
  backlog a `hold` decision carries (`waiting_backlog`); a retry mechanism
  would read from the same place WI-8's digest will.
- `scripts/gather-*.sh` — a new work source (or an extension of an existing
  one) is the natural shape for "a pull request the budget held, whose
  window has since rolled over" to become selectable work again, the same
  way `dequeued`/`merge-conflicts` already turn a stalled-for-a-reason pull
  request back into something a cycle picks up.

## Suggested fix

A new Co-Ordinator source (or a Script-side sweep, matching whichever
existing `gather-*.sh` shape fits best) that lists open, non-draft,
`pr_label`-carrying pull requests still standing at a fresh
`merge_budget_decide` `arm` after their last `merge-budget-hold` — i.e. the
budget has since cleared — and re-enters `run_landing_stage`'s own gate
sequence for them (or a narrower re-check reusing the same gates) rather
than waiting for a human's click. Scope this against WI-8's own digest
(#411) first: a visible backlog a human clears by hand may be judged
sufficient, in which case the right resolution is `not-debt`, not a build.
