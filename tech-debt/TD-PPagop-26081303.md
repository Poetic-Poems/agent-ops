title: Void shapes with no actioned signal never retire, so the extract still grows without bound
status: in-progress
filed: 2026-08-13

Requirement 34n retires a void entry once it is both actioned and old, and
"actioned" is defined by the only two signals that exist: requirement 34k's
`void-object-closed` (recorded by `scripts/close-void-github-items.sh`, which
acts on the bare-issue-number and `pr-<n>-…` shapes and no others) and a
tech-debt register row reading `resolved`/`not-debt`. Every other item id the
pipeline can void has no actioned signal defined for it at all, so it never
retires and the extract keeps the same unbounded growth curve underneath the
bounded part:

- `review-<date>-R-<n>` — a project-review recommendation ref (requirement 15);
- an implementation-plan task id (`W10-breach-handling`);
- `dependabot-alert-<n>` and `code-scanning-alert-<n>`
  (`scripts/gather-findings.sh`);
- `register-hygiene-<12 hex>` (`scripts/gather-register-hygiene.sh`);
- `failed-run-<workflow basename>`;
- a void naming no repo at all — the hand-appended form requirement 34c
  allows, which can match no actioned pair by construction.

`register-hygiene-<hash>` matters most, because its id is minted per
occurrence rather than naming a durable object: the hash is scoped to the
register state that produced it, so no two ever coalesce and every one that
is voided leaves a permanently unretirable entry behind. The alert refs come
next, one per alert ever filed; `failed-run-` is bounded by the repo's
workflow count and a review ref by the weekly review's own numbering, so
those grow slowly rather than not at all. Requirement
34n's own text states this limit, so the behaviour is documented and
deliberate — what is not yet decided is what closes it.

## Suggested direction

Two candidate rules were filed with this item:

- an **age-only** retirement at a longer threshold (a multiple of
  `void_retire_after_days`, or its own config key) for shapes that have no
  actioned signal, on the argument that a void nothing can ever action is
  precisely the one that will never earn its exit; or
- an **actioned signal per shape** — a merged pull request for a review ref
  and a plan task (requirement 34i already reads both, via
  `scripts/gather-review-status.sh` and `scripts/gather-plan-status.sh`, for
  the blocked set), and the alert's own state for an alert ref — leaving only
  the per-occurrence shapes, which may be better served by not recording
  void state against a one-shot id in the first place.

## Direction (decided 2026-08-13, PR #311 review follow-up)

Age-only retirement is rejected outright: a void whose id is **still being
gathered** — a `dependabot-alert-<n>` whose alert is still open, a
`register-hygiene-<hash>` whose register state has not moved on, a
`failed-run-<workflow>` still failing — is doing live suppression work every
cycle. Retiring it on age alone re-exposes the item, the Co-Ordinator
selects it, an engagement is spent re-deriving the same verdict, and a fresh
`item-void` restarts the clock: the rediscovery churn requirement 34k exists
to stop (poetic-fiddle #190/#214 were re-derived void on 7+ cycles), bought
back at one paid engagement per threshold period per item.

The actioned analogue these shapes actually have is liveness: **the source
no longer yields the id**. The decided rule, per shape class:

- For the shapes the cycle already gathers as structured data each cycle
  (the alert refs, `register-hygiene-<hash>`, `failed-run-<…>`): retire once
  the id is (a) absent from the current cycle's own gather for its source,
  decided only when that source's gather succeeded (`source-state` `ok` —
  requirement 34i's own "unknown is not gone" direction), and (b)
  `void_retire_after_days` old. A one-shot `register-hygiene-<hash>` then
  retires as soon as the register moves on; an alert ref once its alert is
  closed or dismissed; a still-live id keeps its void, load-bearing,
  indefinitely.
- For the shapes the cycle does not pre-fetch (a review ref, a plan task
  id): requirement 34i's existing on-demand readers
  (`scripts/gather-review-status.sh`, `scripts/gather-plan-status.sh`) are
  the actioned signal, run over the void residue the same way requirement
  34n already runs the register read — a cost bounded by the recorded
  `void-retired` facts, which guarantee no id is ever re-queried once
  settled.
- A void naming no repo — the hand-appended form requirement 34c allows —
  still never retires; a human's own line is left for a human to retract.

Every retirement under this rule records the same `void-retired` fact
requirement 34n now writes, so the decision is taken once and the growth
curve stays flat.

Acceptance stays as filed: a test per named shape in
`test/cycle-state.test.sh`, and nothing changes about what counts as void.

Filed by the Reviewer of `Poetic-Poems/agent-ops#311`, which implements
requirement 34n and bounds the classes that made up the bulk of the
122-entry extract behind issue #309.

## Addendum (2026-08-13, PR #332)

A shape joined this class after filing: **`pr-<n>-conflict-<head-sha>`**, the
merge-conflicts ref (requirement 3g). TD-PPagop-26080901 excluded it from
requirement 34k's close — it names a live pull request the void says nothing
about closing — so it no longer earns a `void-object-closed` and, like the
shapes above, never retires.

It belongs to the **first** class in the decided rule: the cycle already
gathers it as structured data every cycle
(`scripts/gather-merge-conflicts.sh`), and the source stops yielding the id
the moment the conflict resolves, which is the same moment the item goes
void. So the liveness rule reaches it with nothing new to design — but it
must be named in the implementation, because it is the one shape here whose
id is minted **per occurrence**: a fresh head SHA mints a fresh id, so no two
ever coalesce, exactly the property that makes `register-hygiene-<hash>`
the worst of the original set. Merge conflicts recur far more often than
register-hygiene findings do, so on current behaviour this shape is the
fastest-growing contributor to the extract.

Note the interaction with TD-PPagop-26081304: if that item restores a close
for the *superseded-Dependabot* half of this shape, that half retires through
`void-object-closed` again and only the conflict-resolved half needs the
liveness rule.
