`TD-PPagop-26082201` stopped `test/config-schema.test.sh`'s `assert_doctor`
fixtures from inheriting the ambient `PULLWRIGHT_APPROVER_APP_ID`,
`PULLWRIGHT_APPROVER_INSTALLATION_ID` and `PULLWRIGHT_APPROVER_PRIVATE_KEY_PATH`
by clearing them in `_assert_doctor_check` before every `doctor.sh`
invocation. That made the reconciliation `scripts/doctor.sh` performs between
a set `PULLWRIGHT_APPROVER_APP_ID` and a set `approver_app_id`
(`lib/approver-token.sh`) invisible to the suite — which is correct for every
existing fixture, none of which is about that rule — but it also means the
rule itself now has no coverage at all: its only prior appearance in the
suite was as the accidental three-assertion inversion the same item fixed.

## Suggested fix

Add a fixture that sets `PULLWRIGHT_APPROVER_APP_ID` to one value and the
fixture's own `approver_app_id` to a different one (via `env` around the
`bash scripts/doctor.sh` call, the same way `_assert_doctor_check` now clears
the three variables), and asserts `doctor.sh` fails and names the mismatch —
turning the trap `TD-PPagop-26082201` found into the positive test it should
have been from the start.
