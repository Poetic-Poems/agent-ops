Issue #684 documented D4's primary BYO API-key path alongside the existing
subscription-OAuth documentation in `deploy/docker/.env.example`,
`deploy/docker/compose.yaml`, `deploy/docker/README.md` and
`scripts/doctor.sh` — the four files the issue scoped. The top-level
`README.md` was out of scope for that item, but it carries the same
one-sided framing in its own deployment overview: the "Five things worth
knowing" list (`README.md`, "Authenticate once per node") states the
interactive `docker compose exec scheduler claude` login as though it were
the only way to give a node model credentials, with no mention of
`ANTHROPIC_API_KEY`. The "Decommissioning a node" section's `claude-config`
volume note has the same one-sided framing.

Suggested fix: update both spots to name the BYO API-key path as primary
(D4) and the OAuth login as the documented alternative with its constraints
(interactive per node; own use only), consistent with the wording now in
`deploy/docker/README.md`.

Noticed while working PR for issue #684.
