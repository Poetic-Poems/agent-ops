**What.** #879 moves the Implementer's and Reviewer's own deferred-work
conventions off the in-repo register and onto labelled GitHub issues (`gh
issue create --label pw::type:tech-debt` plus a `Defers: #n` line), and
resolving a debt item now closes an issue (`Fixes #n` plus a `td-record`
body block) rather than flipping a `tech-debt/<id>.md`'s frontmatter. But
`lib/tech-debt-file.sh`'s `techdebt_file_debt` — the deterministic path the
Approver and the Enabler use (via `file_debt` in their own final JSON, per
`lib/approver.sh` and requirement 36c) to file a shortcut *they* notice,
never through an LLM prompt — still reserves a `td/<id>` id with
`scripts/reserve-tech-debt-id.pl`, commits `tech-debt/<id>.md` on a
`td-record/<id>` branch, and opens a pull request carrying it alone. That is
the exact register-file mechanism #879 retires everywhere else, so a
tech-debt item the Approver or the Enabler files today still lands as a
register row, not a labelled issue — invisible to `scripts/gather-tech-
debt.sh`'s issue-only band until some later migration also converts it.

**Why it matters.** Two live conventions for the same "file a debt item"
action, in the same pipeline, diverging on which one a given stage happens
to use — an Implementer/Reviewer shortcut becomes an issue with a `Defers:`
line; an Approver/Enabler shortcut becomes a register file nothing currently
reads back into the band. Left alone, this is the same "two implementations
of one rule" gotcha this repository's own spec already names, and it grows
the pile of register items the roadmap's later retirement issue has to
migrate one by one instead of shrinking it.

**Where.**

- `lib/tech-debt-file.sh` — `techdebt_file_debt`, `techdebt_record_body`,
  the whole `td-record/<id>`/`td/<id>` reservation-and-branch machinery
- `lib/approver.sh` (~line 642) and requirement 36c — the two callers
- `docs/IMPLEMENTATION-PIPELINE-SPEC.md` requirement 17g, the reservation-
  release retry sweep, and `scripts/sweep-orphan-branches.sh` — all built
  around this same `td-record/`/`td/` shape and would need to move with it

**Suggested fix.** Give the Approver/Enabler path a `techdebt_file_debt`
equivalent that calls `gh issue create --label pw::type:tech-debt` directly
(one API call, no branch, no reservation, no pull request — exactly the
shape #879 gives the Implementer) instead of reserving an id and opening a
filing PR, and retire the id-reservation/branch machinery this file owns
once nothing calls it. Deliberately left out of #879 itself: that issue's
own scope names only `lib/claim.sh`, `prompts/implementer.md`,
`prompts/reviewer.md` and the pipeline spec, and this is a materially
different code path (deterministic Script code under a different pair of
stages) the roadmap's decomposed register-retirement issues are the more
natural place for.

**Provenance.** Noticed while working #879 (PR #949).
