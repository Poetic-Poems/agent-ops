title: A human-visibility violation the sweep cannot self-heal surfaces only as a log warning, not as work
status: in-progress

---

Issue #242's fourth bullet asked for "a periodic (cheap, deterministic) audit
[that] asserts the invariant: no open item classified human-waiting without a
corresponding dashboard-visible handle; violations raise a register-hygiene
finding". Requirement 38c (`scripts/sweep-human-visibility.sh`) delivers the
audit and goes further for the common case — it *fixes* the violation in the
same pass rather than reporting it — which is the better answer wherever the
fix is available to it. What it does not deliver is the second half: a
violation the sweep cannot fix becomes a `warning` event and nothing more, and
a `warning` is not selectable work. Nothing re-reads it, nothing tracks whether
it recurred, and the human it concerns is by definition not looking (that is
what the violation *is*).

The residual cases, all of which the sweep reaches and none of which it can
correct:

- a `gh` read or the review-request POST that fails — GitHub unreachable, the
  token's scopes wrong, `enabler_assignee` not a collaborator on that repo;
- a pull request whose only candidate reviewer is its own author, which
  `ensure_human_reviewer` correctly declines to 422 over
  (`lib/handoff.sh`) — nobody is asked, and the `skip` is silent by design;
- an issue human-blocked by some classification other than the two requirement
  38 covers (the Co-Ordinator's `needs_refinement`, requirement 38b, and the
  Enabler's `escalate`, requirement 36a). Requirement 38d records that scope
  limit deliberately; this item is the gap it leaves.

Fix: add a `human-visibility` finding to the register-hygiene source
(`scripts/gather-register-hygiene.sh`, requirement 3i) — or a sibling gatherer
alongside it — so a violation the sweep could not heal becomes an ordinary
selectable work item with the pipeline's existing escape path, exactly as a
register inconsistency already does. The audit itself already exists and is
already deterministic; what is missing is a gatherer that reads its warnings
back out of the log union (or re-runs it in a read-only mode) and presents them
as work. Requirement 38c and requirement 38d in
`docs/IMPLEMENTATION-PIPELINE-SPEC.md` both need updating when this lands, as
does the PR #257 body's "Deliberately out of scope" note that this record
replaces.
