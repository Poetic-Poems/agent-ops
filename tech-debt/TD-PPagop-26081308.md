Requirement 34k's leading example is an obsolete draft pull request that
"stayed open on GitHub, visible to every human and to every tool that reads
the repository rather than this pipeline's own log, and kept being re-derived
void by cycle after cycle with nothing ever said to it" (issue #240;
poetic-fiddle #190/#214 were re-derived void on 7+ separate cycles and never
closed). Closing it needs a *corroborated* void of the item
`pr-<n>-abandoned-<head-sha>` that names it.

TD-PPagop-26080807 gave that shape a live corroboration check
(`void_finishing_pr_reason`, `lib/void-guard.sh`), and #337 calibrated what
the check demands to what 34k then does with the void: because a corroborated
`-abandoned-` or `-review-` void makes 34k *close* the pull request, an open
pull request corroborates one only when its diff against its base is empty.
An obsolete draft is open **and** carries a real diff — being obsolete is
precisely why its changes are not on the base — so its void is refused, the
item is recorded `blocked`, the Enabler adjudicates it through the same guard
and refuses it again, and a human gets an escalation issue instead of a
closed pull request.

That is the intended trade and it is the safe direction: "this draft is no
longer wanted" is a judgement no API call can corroborate, and a pipeline
that closes live branches on an uncorroborated judgement destroys work — it
did, in TD-PPagop-26080901, taking pull request #264 and a human
`CHANGES_REQUESTED` review round with it. This item records the capability
the trade costs, not a defect in it.

The cost: 34k's pull-request close now only ever fires for a pull request
whose diff is already empty against its base (the "already landed elsewhere"
case). The obsolete-draft case that motivated requirement 34k reaches a human
by escalation instead. Escalation is not free — it is a human's attention per
occurrence, on exactly the class of object that accumulates, and the item
itself is inert either way (`gather-abandoned-drafts.sh` mints a new id per
head sha, so an untouched draft keeps re-presenting the same blocked item
rather than looping).

Note the neighbouring gaps in the same area, which interact:
TD-PPagop-26081304 (a superseded Dependabot bump is voided but no longer
closed, because it shares the `-conflict-` id shape) and TD-PPagop-26081303
(shapes with no actioned signal never retire from the void extract).

## Suggested fix

The question to settle is what evidence, short of a human, may stand for "no
longer wanted". Three directions, roughly in order of cost:

1. **A corroborable obsolescence signal on the pull request itself.** Rather
   than trusting the writer's prose, require something the API can confirm
   that means the work is unwanted — a closing keyword resolved elsewhere, a
   `wontfix`/`obsolete` label a human applied, or the base branch having
   deleted the files the draft touches. The void then corroborates on that
   signal instead of on an empty diff.
2. **Let the escalation close it.** Keep the guard as it is and give the
   escalation issue an explicit "close the pull request" affordance, so the
   human decision is one click rather than a separate manual chore. This
   concedes the automation but removes most of the per-occurrence cost.
3. **A separate, weaker verdict than `void` for "unwanted".** A void is
   terminal and only `unvoided` undoes it, which is why its corroboration is
   strict. A distinct verdict that closes the pull request but is cheaper to
   reverse would let the strict void rule stand unchanged. This is the
   largest change and touches requirements 34c, 34d and 34k together.
