**What:** PR #892 (TD-PPagop-26082308) replaced `landing_approver_adjudication_history`'s per-round source convention (`$log_file` on the first-approval round, `$union_log` on a 2.1e re-arm) with an unconditional deduplicated union of both, and updated the function's own header and requirement 8x — but two comments elsewhere still describe the old convention. (1) test/landing-audit-record.test.sh, the harness comment above the LOG_SEED_FILE/UNION_SEED_FILE seeding (near line 118): 'the same file _landing_stage_attempt itself reads (non-retry) or $union_log (retry)' — the sibling comment in test/landing-wiring.test.sh was updated in the same PR, this one was missed. (2) lib/landing.sh's `landing_open_question_latest` header (near line 2025): 'SRC follows `landing_approver_adjudication_history`'s own convention: `$log_file` on the round that first raises a question … or `$union_log` when read back later' — a cross-reference to a convention the named function no longer has (and callers of `landing_open_question_latest` itself read `${union_log:-$log_file}`, so the description was already drifting). **Why it matters:** both comments send a reader to reason from a source-selection rule that no longer exists, in exactly the code where the distinction between the two logs is subtle enough to have produced TD-PPagop-26082308 in the first place. **Where:** test/landing-audit-record.test.sh ~118-120; lib/landing.sh ~2025-2029. **Suggested fix:** reword the harness comment to say both files are read as a deduplicated union on every round, and rewrite `landing_open_question_latest`'s SRC paragraph to state its own convention directly (callers pass `${union_log:-$log_file}`) instead of citing the other function's. Comment-only change; no behaviour or spec edit needed.

Noticed while the Approver was judging https://github.com/Poetic-Poems/agent-ops/pull/892.
