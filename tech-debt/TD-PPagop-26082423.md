lib/landing.sh's _landing_routine_sources and scripts/detect-classifier-escapes.sh's _escape_audit_routine_sources both end in the shipped literal ["register-hygiene","tech-debt"]. test/detect-classifier-escapes.test.sh pins the two functions equal over a battery of configs (including '{}', which compares literal against literal), but nothing pins either literal against .properties.merge_autonomy_routine_sources.default in config.schema.json — the pin the same test file does add for merge_autonomy_protected_paths (test/detect-classifier-escapes.test.sh:160-165), with a comment explaining why the pair-pin alone is insufficient. The production asymmetry that comment names applies to the sources key too: agent-cycle.sh:4498 calls landing_eligible with $DEFAULTED_CONFIG (schema default already materialised into the top-level key, so the gate's literal is never reached), while detect-classifier-escapes.sh:517 reads the raw --config file and does reach its own literal when the key is absent. An edit to the schema default for merge_autonomy_routine_sources would therefore move the gate without moving the post-hoc auditor and no test would fail: widening manufactures classifier-escape reports for legitimately landed pull requests from the newly admitted source, narrowing lets the auditor's stale wider literal read a genuine gate escape as clean — the two failure modes requirement 8e exists to rule out. Suggested fix: add the same two assert_eq lines the protected-paths block uses, asserting _landing_routine_sources '{}' and _escape_audit_routine_sources '{}' each equal jq -c '.properties.merge_autonomy_routine_sources.default' config.schema.json. This predates PR #729 (which repeats the same pattern for the new merge_autonomy_routine_complexity key and is being asked to add the schema pin for that key in review); the sources pair is out of that pull request's scope, hence this record.

Noticed while the Approver was judging https://github.com/Poetic-Poems/agent-ops/pull/729.
