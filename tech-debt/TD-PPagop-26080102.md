Requirement 18a — the mandatory re-read of a blocked GitHub issue whose
thread has moved, and the `recheck-clean` marker #149 added to stop that
re-read recurring on a thread that has said nothing new — has no numbered
acceptance check. It had none before #149 either, so this is not a
regression, but the spec's own convention is that a numbered check names the
test that proves a requirement (checks 6g, 8c and the metering check all
do), and 18a is now the requirement with the most machinery behind it — the
two-timestamp comparison, the `recheck_clean` report field, the
`recheck-clean` event, and `blocked_items`' fold — with nothing anchored to
it. `test/cycle-state.test.sh` covers the fold half well (no-marker,
fold, newest-wins, repo-scoped and bare-id matching), but no check exercises
the requirement's loop end to end.

Fix: add a numbered acceptance check alongside check 7 ("A blocked verdict
round-trips"), covering both halves of the requirement: a blocked issue
whose `updated_at` is newer than the later of the block's `ts` and its
`recheck_clean_ts` forces the whole-thread re-read, and a `recheck-clean`
recorded by that re-read stops the next cycle repeating it while the thread
stays quiet. Name the test that proves each half, per the spec's convention.

Filed 2026-08-01, from the review discussion on #149.
