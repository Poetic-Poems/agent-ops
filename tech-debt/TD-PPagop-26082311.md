The #590 prose sweep retires the literal words 'hourly'/'weekly' as pipeline identity, but several live passages still quantify per-cycle costs on an assumed one-hour cadence using the phrase 'every hour', which reads wrong on a `schedule.cycle_interval_minutes` installation faster or slower than 60: prompts/coordinator.md:605 and docs/IMPLEMENTATION-PIPELINE-SPEC.md:5698 ('every hour it sits stalled it holds/occupies a back-pressure slot'), docs/IMPLEMENTATION-PIPELINE-SPEC.md:2307 ('every node fails identically every hour'), :7813 ('a wrong unvoid costs a cycle every hour until'), and docs/IMPLEMENTATION-PIPELINE-SPEC.md:16433's design-decision echo. These fall outside #590's literal 'hourly/weekly' criterion and outside #591 (timing behaviour) and #592 (identifiers), so nothing currently owns them. Suggested fix: reword each to 'every cycle' / 'cycle after cycle' or to name `schedule.cycle_interval_minutes`, keeping prompt/spec mirrored pairs in step in the same PR per CLAUDE.md's spec-first rule.
